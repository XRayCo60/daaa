# معماری مغز مصنوعی - پیاده‌سازی C++ (نسخه ۱)

> این سند پیاده‌سازی فنی سند مفهومی اصلی است. زبان پیاده‌سازی C++17، هدف ۱۰ تیک بر ثانیه حداقل، اجرا روی i7-2670QM بدون AVX2 و بدون CUDA.

## ۱. انتخاب مدل ریاضی نورون

سه گزینه بررسی شد:
- LIF: خیلی ساده، ارزان ولی رفتار متنوع ندارد.
- Hodgkin-Huxley: بیولوژیک دقیق ولی برای i7 خیلی سنگین (۴ معادله دیفرانسیل + اکسپوننشیال).
- **Izhikevich (انتخاب نهایی)**: فقط ۲ متغیر و ۴ پارامتر، با یک رشته فرمول رفتارهای burst, chatter, fast-spike و ... را شبیه‌سازی می‌کند. هزینه تقریباً مثل LIF، تنوع مثل HH.

فرمول:
```
v' = 0.04*v^2 + 5*v + 140 - u + I
u' = a*(b*v - u)
if v >= 30: v = c; u += d
```
- `I` = مجموع ورودی سیناپسی + جریان خودجوش + نویز
- پارامترهای a,b,c,d قابل تغییر در فاز "نرمی" هستند (خود-اصلاح منطق).

## ۲. گراف نامنظم
- هر نورون حداکثر ۲۰ خروجی.
- ۱۸ تا `known=true` یعنی نورون می‌داند به کجا وصل است.
- ۲ تا `known=false` یعنی مسیر مخفی - نورون نمی‌داند مقصد کجاست، فقط بعداً از طریق همبستگی خروجی فارسی می‌فهمد (motor babbling).
- ورودی: بخشی از نورون‌ها `is_input=true` - بخشی از ورودی‌هایشان از بیرون (برنامه) می‌آید. این همان "چند بخش داشتن مغز" است.

## ۳. چندبخشی بودن مغز (Regions)
مغز به ناحیه‌ها تقسیم شده:
- `InputRegion`: نورون‌هایی که بخشی از ورودیش از runner قابل نوشتن است (`external_writable`)
- `ProcessingRegion`: گراف میانی
- `OutputRegion`: نورون‌هایی که خروجیشان به انکودر زبان وصل است (نه به نورون دیگر)
- `MemoryRegion`: نورون‌های حافظه‌ای
- `EfferenceRegion`: نورون‌های ناظر که بافر efference copy را می‌بینند

هر Region یک فلگ `meaningful` دارد - کاربر می‌تواند از runner بگوید "این بخش معناداره" تا تمرکز مانا و دیباگ.

## ۴. سیستم مانا
- هر نورون `mana: float`
- هر اسپایک هزینه: 0.7 مانا. اگر مانا < هزینه و نورون حالت عادی است -> نمی‌تواند فایر کند.
- در حالت تشنج: بدون مانا اسپایک می‌زند ولی از `integrity` سیناپس‌هایش کم می‌شود (سوزوندن ساختار فیزیکی).
- منابع مانا:
  1. Blood pool: استخر مشترک double. وقتی کدک یک کلمه معنادار (عضو دیکشنری ساده) تشخیص دهد -> به pool تزریق می‌شود. نورون‌ها توزیع‌شده برمی‌دارند.
  2. P2P gift: نورون A می‌تواند به B مانا هدیه دهد.
  3. تزریق بیرونی: از runner (`inject` کامند).
- نورون نمی‌تواند مبدا مانا را تشخیص دهد - فقط `mana += amount` می‌بیند (یادگیری علی باید از تجربه کشف شود).

جوانه‌زنی: اگر mana > 100، نورون اجازه دارد فرزند بسازد (هزینه 50 مانا). فرزند یک گراف کوچک از والد کپی می‌کند با جهش.

## ۵. شکست، تشنج، مرگ
- استرس = `noise_level + (1 - mana/ threshold)`
- اگر استرس > 0.8: احتمال 10% برود در `IGNORE` (کر شدن موقت) یا `SEIZURE`.
- IGNORE: برای N تیک ورودی را نادیده می‌گیرد.
- SEIZURE: بدون گرفتن ورودی، به 3-5 مسیر رندوم اسپم می‌فرستد، integrity مسیرها -= 0.1
- اگر یک نورون 3 بار متوالی بدقلقی کند -> `PERMANENT_IGNORE`
- همسایه‌ها اگر ببینند نورون مقصد در PERMANENT_IGNORE است، خودشان تصمیم می‌گیرند اتصال را قطع کنند و به نورون دیگری وصل شوند (pruning توزیع‌شده).
- اگر نورونی هیچ ورودی و خروجی نداشته باشد -> حذف فیزیکی (garbage collect) - برگشت‌ناپذیر.

## ۶. حافظه محلی و بافر efference copy
- نورون معمولی: `local_memory[256] byte` - هرچه می‌خواهد می‌نویسد (تاریخچه تغییر تابع، مسیر ۲۱ و ...).
- نورون حافظه‌ای: `local_memory[8192]` + `storage_arch_id` که هر ۲۰۰ تیک می‌تواند معماری داخلی‌اش را بازنویسی کند.
- بافر efference: حلقه 1024 اسلات از آخرین خروجی‌ها. تاخیر عمدی 5 تیک دارد تا لوپ آنی نشود. EfferenceRegion‌ها این بافر را می‌بینند و تصمیم می‌گیرند چه چیزی را به مغز تزریق کنند (توجه خودجوش).

## ۷. کدک برگشت‌پذیر (نقطه طلایی ایده)
نیاز سند:
> تابعی که ورودی خارجی رو تبدیل به 0 و 1 میکنه دقیقاً باید معکوس سیستمی باشه که الگوها رو به حروف فارسی تبدیل میکنه باشه

یعنی `decode(encode(c)) == c` و `encode(decode(b)) == b` - یک bijection واقعی بدون اتلاف.

پیاده‌سازی:
- الفبای پایه ۴۰ کاراکتر: ۳۲ حرف فارسی + فاصله + نقطه + ویرگول + ؟ + ! + newline + آ + ء + ئ + ؤ (برای پوشش). برای راحتی به ۶۴ می‌رسانیم (۶ بیت) تا جای توسعه باشد.
- هر کاراکتر = یک الگوی ۶ بیتی یکتا (مثلاً ا=000000, ب=000001...).
- اما الگوی نورونی واقعی فقط ۰/۱ نیست - ما آن را به بردار فایرینگ ۶ نورون خروجی نگاشت می‌کنیم.
- بنابراین:
  - `encode(PersianChar) -> uint6_t (0..63) -> bitset<6> (0/1)`
  - ورودی خارجی: متن فارسی -> encode -> جریان ۰/۱ -> به نورون‌های InputRegion به عنوان جریان I تزریق می‌شود.
  - خروجی: فایرینگ OutputRegion (۶ بیت) -> decode -> حرف فارسی.
  - این دو معکوس دقیق هم هستند. تست ریاضی bijection در `codec_test`.

این کدک در فایل .afu هم ذخیره می‌شود تا مدل و runner همیشه هماهنگ باشند.

## ۸. نرمی (پلاستیسیته موقت)
- تایمر softness: با تزریق مانا + سیگنال تایید شروع می‌شود (مثلاً 50 تیک).
- یک پنجره یک‌بارمصرف است: به محض استفاده از یکی از این سه، فوراً تمام می‌شود:
  1. تغییر تابع ریاضی: a,b,c,d نورون عوض شود (self-modifying logic)
  2. تغییر اتصالات رایگان: تغییر مقصد بدون هزینه مانا
  3. ساخت مسیر ۲۱ام: شکستن سقف ۲۰
- نورون بعد از پایان، نوع تغییری که کرد را در `last_softness_choice` ذخیره می‌کند - به مرور یک ترجیح شخصی می‌سازد (کدام نوع بیشتر جواب داده).

## ۹. فاز VM
- یک فلگ bool در مغز: `vm_mode`
- false -> خروجی از طریق codec فارسی به کاربر
- true -> خروجی مستقیم به ترمینال VM (فعلاً شبیه‌سازی شده، بعداً pipe واقعی)
- معیار پاداش یکسان: اجرای موفق کد = کلمه معنادار = تزریق مانا؛ خطا = نویز = تنبیه.

## ۱۰. فایل .afu
فرمت باینری خودکفا (مثل GGUF):
- magic: 'AFU1' (0x31465541 little-endian)
- version: u32
- counts: neuron, synapse, region, codec
- blood_mana f64, tick u64
- سپس آرایه نورون‌ها (packed)
- سیناپس‌ها
- regionها
- جدول codec (char utf8 + pattern)
- CRC32 footer

runner این فایل را load می‌کند و اجرا می‌کند. مدل و runner جدایند.

## ۱۱. سیستم CUDA و تقسیم بار
- اینترفیس `IDevice` با دو پیاده‌سازی:
  - `CpuDevice`: همیشه available، اجرای نورون‌ها با حلقه OpenMP-مانند (بدون نیاز به AVX2).
  - `CudaDeviceStub`: روی این لپتاپ always dormant (چون Intel HD 3000 + CUDA NVIDIA-only). ولی اینترفیس کامل است: available() -> چک nvidia-smi, execute() -> اگر gpu نبود fallback به cpu. وقتی بعداً روی سیستم قوی (GTX 1050 / T4...) رفتیم بدون تغییر کد فعال می‌شود.
- تقسیم بار: اگر CudaDevice available باشد، `compute()` بخش محاسبه تابع نورون (batch) روی GPU، تصمیمات ساختاری نادر (جوانه‌زنی، قطع اتصال) روی CPU باقی می‌ماند - دقیقاً طبق نکته سند بخش ۱۱.

## ۱۲. سرعت متغیر و بودجه CPU
- نیاز: حداقل ۱۰ تیک بر ثانیه، یعنی زمان مدل ۱۰ برابر سریع‌تر از واقعیت حس شود.
- runner دارای:
  - `tps_min=10`, `tps_max=100` (سقف و کف)
  - `cpu_percent` (تنظیم بودجه: مثلاً 70%)
- لوپ: اندازه‌گیری زمان هر تیک، اگر سریع‌تر از سقف بود sleep کن، اگر کندتر از کف بود هشدار بده.
- بودجه CPU: اگر `cpu_percent=30%`، یعنی در هر ثانیه فقط 300ms اجازه محاسبه داری، بقیه sleep. این مانا را هم تحت تاثیر قرار می‌دهد (محدودیت منابع = درد).
